The release workflow publishes the image to GitHub Container Registry:

```text

ghcr.io/tuxmint-open-source/memtly-heic-converter:memtly-1.0.6-v0.1.0-rc.1
```

Do not use `latest`; no `latest` tag is published for this pre-release.

## What is included

- Browser-side HEIC/HEIF still-image conversion to JPEG before Memtly's upload path.
- Feature flag disabled by default in the image.
- Existing server-side allow-list remains `.jpg,.jpeg,.png,.mp4,.mov`.
- Sequential conversion and bounded detection/resource controls.
- Fail-closed behavior for malformed HEIC-hinted files.
- Third-party license notices and fixture provenance.

## Known limitations

- This is a pre-release candidate, not a stable production-ready release.
- Real iPhone/iPad Safari hardware validation remains outstanding.
- JPEG output is a derivative and does not preserve the original HEIC bitstream.
- EXIF/XMP metadata and original capture time may be lost.
- HEIF sequences, Live Photo auxiliaries, depth maps, and multi-image HEIF content are not preserved by this browser-conversion slice.
- Browser memory behavior on real mobile devices still requires hardware validation.
- HEVC/HEIC patent considerations may matter in some jurisdictions; open-source licensing is not a patent opinion.

## Upgrade and enablement

Use the published image by digest or immutable tag in a controlled validation deployment. Enable the conversion feature explicitly:

```dotenv
GALLERY_CLIENT_HEIC_CONVERSION=true
```

Keep Memtly's server allow-list unchanged:

```dotenv
GALLERY_ALLOWED_FILE_TYPES=.jpg,.jpeg,.png,.mp4,.mov
```

## Rollback

Rollback by switching back to the unmodified Memtly/foundation image and redeploying without deleting volumes or database data. The lifecycle validation report records that this rollback path was exercised for the candidate line.
